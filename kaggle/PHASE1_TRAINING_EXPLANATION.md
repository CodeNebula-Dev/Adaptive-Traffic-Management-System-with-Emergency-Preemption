## 1. High-Level Objective

Phase 1 trains ATMS-Net's **custom 13.2M parameter YOLO-style single-stage object detector** from random initialization (from scratch) on the **MS COCO 2017 vehicle subset**.

The goal of Phase 1 is **feature learning**: teaching the convolutional backbone to recognize visual features of 4 target vehicle types (`car`, `motorcycle`, `bus`, `truck`) under diverse conditions (lighting, angles, occlusions) before fine-tuning on intersection camera feeds in Phase 2.

---

### Detection Strides & Receptive Fields

For an input resolution of $416 \times 416$ pixels, the network outputs predictions across 3 spatial grid scales:

$$\text{Grid Size} = \frac{\text{Input Size}}{\text{Stride}}$$

1. **Stride 8** $\rightarrow 52 \times 52 = 2,704\text{ cells}$:
   - Each grid cell covers an $8 \times 8$ pixel region.
   - Designed to detect **small objects** (e.g., motorcycles or distant cars).
2. **Stride 16** $\rightarrow 26 \times 26 = 676\text{ cells}$:
   - Each grid cell covers a $16 \times 16$ pixel region.
   - Designed to detect **medium objects** (e.g., standard sedans, SUVs, small trucks).
3. **Stride 32** $\rightarrow 13 \times 13 = 169\text{ cells}$:
   - Each grid cell covers a $32 \times 32$ pixel region.
   - Designed to detect **large objects** (e.g., buses, articulated trucks, close-up vehicles).

**Total spatial prediction cells per image:**  
$$2,704 + 676 + 169 = 3,549\text{ predictions}$$

---

### Exponential Moving Average (EMA)

EMA maintains a "shadow copy" of model weights $\theta_{\text{EMA}}$ updated after each training step:

$$\theta_{\text{EMA}} \leftarrow \beta \cdot \theta_{\text{EMA}} + (1 - \beta) \cdot \theta_{\text{current}}$$

Where $\beta = 0.9999$.

- **Why use EMA?** Raw SGD updates cause model weights to fluctuate due to mini-batch noise. EMA acts as a temporal low-pass filter, averaging out noise.
- **Validation:** Validation metrics (mAP@0.5) are computed on the EMA weights, producing higher stability and typically **+1.5% to +3% higher mAP**.

### What is an Epoch & Batch?

- **1 Epoch** means **one complete pass through the entire training dataset** (all 14,519 images).
- Because processing 14,519 images at once is too large for GPU VRAM, images are grouped into mini-batches of **32 images at a time** (`batch_size = 32`).
- 1 Epoch consists of **453 batches** ($\lceil 14,519 / 32 \rceil = 453\text{ iterations}$).

During **Epoch 1**, the model processes all 453 batches, seeing every image in the training set once. Training for **50 Epochs** allows the model to see the entire dataset 50 times under different random augmentations (mosaic, color jitter, flips), allowing the weights to adjust gradually and maximize object detection accuracy.

---

### Data Augmentation Pipeline

To prevent overfitting during 50 epochs, the training pipeline applies random augmentations on the fly:

1. **Mosaic Augment ($p=0.5$):** Combines 4 random training images into 1 composite tile. Forces the model to detect objects at smaller scales and varying context.
2. **HSV Color Jitter:** Randomly alters Hue ($\pm 1.5\%$), Saturation ($\pm 70\%$), and Brightness/Value ($\pm 40\%$) to simulate different lighting conditions (day, overcast, shadows).
3. **Random Horizontal Flip ($p=0.5$):** Flips images horizontally while updating bounding box coordinates.
4. **Cutout ($p=0.5$):** Randomly erases square patches to enforce robustness against partial vehicle occlusions.

## 4. Optimizer & Training Dynamics (`[Optimizer]`)

```text
[Optimizer]
  → Optimizer: SGD (lr=0.01, momentum=0.937, wd=0.0005)
  → Parameter groups: BN=66, Conv=75, Bias=75
  → Scheduler: Cosine annealing (warmup=3 epochs)
  → Mixed precision (FP16) enabled
```

### Term-by-Term Explanation

| Term | Value | Detailed Technical Meaning |
|------|-------|----------------------------|
| **Optimizer** | `SGD` | Stochastic Gradient Descent with Nesterov momentum ($0.937$) and L2 weight decay ($0.0005$). |
| **Learning Rate (lr)** | `0.01` | Peak initial learning rate after warmup. |
| **Momentum** | `0.937` | Accelerates SGD vectors in the right direction and dampens oscillations ($v_t = \gamma v_{t-1} + \eta \nabla L$). |
| **Weight Decay (wd)** | `0.0005` | $L_2$ regularization penalty on convolutional weights to prevent overfitting ($\lambda \|w\|^2$). |
| **Parameter Groups** | `BN=66, Conv=75, Bias=75` | Divides network parameters into 3 distinct optimization groups. |
| **Warmup Epochs** | `3` | Linear warmup phase over the first 3 epochs ($1,359$ steps). |
| **Scheduler** | `Cosine Annealing` | Smoothly decays learning rate following a half-cosine wave. |
| **Mixed Precision** | `FP16` | Executes forward/backward passes in 16-bit float using PyTorch `amp.autocast` and `GradScaler`. |

---

### Why Parameter Groups Matter

Not all neural network parameters should be regularized equally:

1. **Conv Weights (Group `pg1`):** Applied weight decay ($0.0005$). Prevents weights from growing excessively large.
2. **BatchNorm Weights & Biases (Group `pg0`):** **No weight decay ($0.0000$)**. Regularizing BN scale parameters destroys normalization stability.
3. **Conv Biases (Group `pg2`):** **No weight decay ($0.0000$)**. Regularizing bias terms causes underfitting.

---

### Learning Rate Schedule (Warmup + Cosine Annealing)

```
LR
^
0.010 |       /---\
      |      /     \
      |     /       \
      |    /         \
0.001 |---/           \___ 0.0001
      +-------------------------> Epoch
        0   3          50
```

1. **Linear Warmup (Epochs 1–3):** Learning rate increases linearly from $0.001$ to $0.010$. This stabilizes initial gradient flow when weights are randomly initialized.
2. **Cosine Annealing Decay (Epochs 4–50):** Learning rate decays according to:

$$\eta_t = \eta_{\text{min}} + \frac{1}{2}(\eta_{\text{max}} - \eta_{\text{min}})\left(1 + \cos\left(\frac{\pi t}{T_{\text{max}}}\right)\right)$$

Where $\eta_{\text{max}} = 0.01$, $\eta_{\text{min}} = 0.0001$, and $T_{\text{max}} = 47$ epochs.

---

### Backpropagation Engine & Enhanced Learning

**Yes, ATMS-Net uses Backpropagation** as the fundamental mathematical mechanism to update all **13,173,691 trainable parameters** during every training iteration.

#### The 4-Step Iteration Loop

For each mini-batch of 32 images:

1. **Forward Pass (`model(images)`):** Input images pass forward through the backbone (`CSPDarknet`), neck (`FPNPANet`), and head (`DetectionHead`) to produce 3,549 bounding box predictions per image.
2. **Loss Calculation (`criterion(predictions, targets)`):** Compute composite loss ($L_{\text{total}} = 0.05 L_{\text{CIoU}} + 1.0 L_{\text{obj}} + 0.5 L_{\text{cls}}$).
3. **Backpropagation (`loss.backward()`):** PyTorch applies the mathematical chain rule to calculate the exact partial gradient ($\frac{\partial L_{\text{total}}}{\partial w_i}$) for every weight $w_i$ in the network.
4. **Weight Update (`optimizer.step()`):** The SGD Nesterov optimizer uses the computed gradients to adjust weights in the direction of steepest descent.

#### Enhanced Learning Mechanics

To maximize feature learning performance beyond basic backpropagation, ATMS-Net integrates three specialized enhancements:

- **SimOTA Dynamic Matching:** Instead of fixed IoU thresholds, SimOTA dynamically pairs ground-truth objects to predicted cells based on cost, producing cleaner, less noisy gradient signals for backpropagation.
- **AMP Gradient Scaling (`scaler.scale(loss).backward()`):** Under FP16 mixed precision, gradients are dynamically scaled up before backpropagation to prevent 16-bit floating-point numbers from underflowing to zero.
- **Exponential Moving Average (EMA):** While backpropagation updates the raw model weights, EMA updates a smoothed "shadow copy" ($\theta_{\text{EMA}} = 0.9999 \theta_{\text{EMA}} + 0.0001 \theta_{\text{current}}$) after every backpropagation step for evaluation stability.

## 6. Loss Functions: Deep Dive

The total training loss $L_{\text{total}}$ is a weighted combination of 3 loss terms:

$$L_{\text{total}} = \lambda_{\text{box}} \cdot L_{\text{CIoU}} + \lambda_{\text{obj}} \cdot L_{\text{obj}} + \lambda_{\text{cls}} \cdot L_{\text{cls}}$$

Where $\lambda_{\text{box}} = 0.05$, $\lambda_{\text{obj}} = 1.0$, and $\lambda_{\text{cls}} = 0.5$.

---

### 1. Box Regression Loss ($L_{\text{CIoU}}$) — Complete IoU

Instead of standard Smooth L1 loss, ATMS-Net uses **CIoU Loss**, which considers overlap area, distance between central points, and aspect ratio mismatch:

$$L_{\text{CIoU}} = 1 - \text{IoU} + \frac{\rho^2(b, b^{\text{gt}})}{c^2} + \alpha v$$

Where:
- $\text{IoU}$: Intersection over Union between predicted box $b$ and ground truth box $b^{\text{gt}}$.
- $\rho(b, b^{\text{gt}})$: Euclidean distance between center points of the two boxes.
- $c$: Diagonal length of the smallest enclosing bounding box.
- $v$: Measures aspect ratio consistency:

$$v = \frac{4}{\pi^2} \left(\arctan\frac{w^{\text{gt}}}{h^{\text{gt}}} - \arctan\frac{w}{h}\right)^2$$

- $\alpha$: Trade-off parameter $\alpha = \frac{v}{(1 - \text{IoU}) + v}$.

---

### 2. Objectness Loss ($L_{\text{obj}}$) — Binary Cross-Entropy

Evaluated for **all 3,549 spatial grid cells** per image. Evaluates whether a cell contains a vehicle center or background:

$$L_{\text{obj}} = -\sum_{i} \left[ y_i \log(\hat{y}_i) + (1 - y_i) \log(1 - \hat{y}_i) \right]$$

Where:
- $y_i \in [0, 1]$ is the soft IoU target assigned by **SimOTA** matching.
- $\hat{y}_i = \sigma(\text{logit}_i)$ is the predicted objectness probability.

---

### 3. Classification Loss ($L_{\text{cls}}$) — Multi-Class BCE

Evaluated **only on positive matched grid cells** (cells containing a ground-truth vehicle):

$$L_{\text{cls}} = -\sum_{i \in \text{pos}} \sum_{c=1}^{4} \left[ y_{i,c} \log(\hat{y}_{i,c}) + (1 - y_{i,c}) \log(1 - \hat{y}_{i,c}) \right]$$

Where $y_{i,c} \in \{0, 1\}$ is the one-hot target class vector for `car`, `motorcycle`, `bus`, or `truck`.

### Epoch 1 Case Study & Initial Behavior Analysis

During Epoch 1 of ATMS-Net training on Kaggle T4 GPU, the following initial results are logged:

```text
Epoch 1/50 (451.4s) — loss: 0.8640 [box: 2.7807, obj: 0.1811, cls: 1.0878]
Val mAP@0.5: 0.0000 | mAP@0.5:0.95: 0.0000
Per-class AP@0.5: car=0.000 truck=0.000 bus=0.000 motorcycle=0.000
```

#### 1. Training Loss Dropped Significantly 📉
- **Total Loss**: **`0.8640`** (down from `> 5.8` at the first batch)
  - `box_loss` (Coordinate position error): **`2.7807`**
  - `obj_loss` (Object presence error): **`0.1811`**
  - `cls_loss` (Classification error): **`1.0878`**

This rapid drop in composite loss proves that backpropagation ($\text{loss.backward()}$) and optimization ($\text{optimizer.step()}$) are functioning correctly. The convolutional layers are quickly learning primitive visual features (contrast edges, color gradients, basic shapes).

#### 2. Why is `Val mAP@0.5` at `0.0000` in Epoch 1? (100% Normal)

A zero mAP in Epoch 1 is **completely expected and normal** when training a 13.2M parameter object detector from scratch:

1. **Warmup Phase:** Epoch 1 operates under a low learning rate ($0.001 \rightarrow 0.01$). Weight updates are conservative to prevent initial gradient explosion.
2. **Confidence Thresholding:** Validation applies Non-Maximum Suppression (NMS) with `conf_threshold = 0.25`. After only 1 epoch, a randomly initialized network does not yet produce predictions confident enough to clear the 25% confidence filter.
3. **Feature Abstraction Hierarchy:** Neural networks learn hierarchically:
   - **Epoch 1:** Edges, textures, light/shadow gradients.
   - **Epochs 2–5:** Vehicle contours, wheels, headlights.
   - **Epochs 6+:** Complete vehicle classification and accurate bounding box localization.

Starting around **Epochs 3–5**, objectness confidence clears the threshold and `mAP@0.5` begins its upward trajectory.

## 8. Checkpoints & Phase 2 Handoff

After training completes, the script outputs two checkpoint files in `/kaggle/working/checkpoints/`:

1. **`best.pt`**: Model weights from the epoch that achieved the highest `mAP@0.5` score. Includes both raw model weights and smoothed **EMA weights**.
2. **`last.pt`**: Model weights from the final epoch (Epoch 50). Used if training needs to be resumed.

### Handoff to Phase 2

The `best.pt` checkpoint contains the pre-trained feature extraction backbone and detection head. In **Phase 2**, this model is loaded locally to:
1. Fine-tune on intersection camera footage (**UA-DETRAC dataset**).
2. Attach the **Lane Density Estimation Head** to compute real-time queue densities for the RL traffic signal controller.
